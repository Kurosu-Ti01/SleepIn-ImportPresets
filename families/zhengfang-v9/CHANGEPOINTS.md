# 变化点清单 · zhengfang-v9

这份清单就是**贡献者的检查表**：导入读不出课时，照着一项一项对照看哪一项和你的学校不一样，
而不是读完整个适配器再重写。左边是适配器声明的变化点，右边是它的默认值。

一个部署只要能靠「取值」表达差异，就**不需要写代码**：只改 `presets/<id>/preset.json` 里的
`config`。全部取值都对不上时，才写 `presets/<id>/override.js` 覆盖某个具名环节。

## 取值表

| 变化点 | 默认取值 | 能否覆盖 | 说明 |
|---|---|---|---|
| `scheduleAction` | `/kbcx/xskbcx_cxXsgrkb.html` | 是 | 课表查询接口路径 |
| `scheduleQuery` | `gnmkdm=N2151` | 是 | 该接口的固定查询串；没有就留空 |
| `sectionTimesAction` | `/kbcx/xskbcx_cxRjc.html` | 是 | 节次时间接口路径 |
| `sectionTimesQuery` | `gnmkdm=N2151` | 是 | 同上 |
| `semesterYears` | `4` | 是 | 本地合成的学期候选回溯几个学年（1—6，候选数 = 学年数 × 2） |
| `assumedTotalWeeks` | `20` | 是 | **总周数的假设值**：该族不报告总周数，这个值会出现在确认弹窗里，用户看得见 |
| `rowContainer.path` | `kbList` | 是 | 课表行数组在响应里的位置；适配器还会退让到 `data.<同名>`，再退让到「响应里唯一的数组字段」 |
| `sectionTimesContainer.path` | `jcList` | 是 | 节次时间行数组的位置，退让规则同上 |
| `weeksEncoding` | `text` | 是 | 周次编码；`text` 支持 `1-16周`、`(单)`、`(双)`、`3周改`，识别不了会报错而不是猜 |
| `groupKeyOrder` | `classId` → `courseCode` | 是 | 分组键的退化顺序；两者都取不到时适配器退化为「课程名 + 教师」 |
| `fields.*` | 见 `family.json` | 是 | 课程名 `kcmc` / 教师 `xm` / 星期 `xqj` / 节次 `jcs` / 周次 `zcd` / 教室 `cdmc` / 教学班 `jxb_id` / 课程号 `kch` |
| `sectionTimeFields.*` | `jc` / `qssj` / `jssj` | 是 | 节次时间行里「节次号 / 开始 / 结束」三个字段名；节次号取不到时按行序补 |

| 探测特征 | 页面路径含 `/kbcx/` | 需要在适配器里改 | 见 `adapter.js` 的 `detect()`：只用不需要发请求的特征，登录页给可照做的提示 |

## 和参考实现不同、需要知道的三处

1. **学期由本地合成，不让用户手输学年**。该族没有学期列表接口，常见做法是让用户敲 4 位学年再选学期。
   我们按当前时间推「学年 × 两学期」生成候选（默认 8 个），并按月份自动选中当前学期，少一次输入。
   代价是候选窗口有限：需要导入更早的学期时，把 `semesterYears` 调大（上限 6 学年 = 12 个候选）。
2. **总周数是声明而不是推测**。该族不报告总周数，默认按 20 周写入，并且**这个值会显示在确认弹窗里**；
   周数不对时用户可以导入后在课程表里改，或把 `assumedTotalWeeks` 改成本校的真实值。
3. **不连续节次会被跳过而不是折叠**。`jcs` 若是 `1,3` 这种非连续写法，适配器报「节次字段不是连续节次」，
   该行进入「跳过的行」列表——因为 payload 的 `from`/`to` 表达不了中间缺的那一节。

## 改这一族时的注意点

- **同一行里的陷阱字段**：`day` / `month` / `year` / `date*` 常是服务端写入的时间戳，**不是星期**；星期取 `xqj`。默认映射不取这些字段，但改这一族时很容易踩。
- **`/jwglxt` 前缀**：正方 v9 的实例普遍部署在 `/jwglxt` 上下文下，所以族默认里不带前缀的路径很可能每所部署都要覆盖——登记在册的方案都按带前缀的形状填了取值。更彻底的做法是在适配器里从 `ctx.pagePath()` 推出前缀（运行时可推断，属于适配器代码，不是取值）。
- **节次时间行**的节次号字段可能是 `jcmc` 而不是 `jc`；两个接口的查询串（`gnmkdm`）有的部署不需要。
- **已知的族缺口**：节次时间接口若把行数组放在响应的**最外层**（根数组），`rowsFor` 只认 `jcList` 这类命名容器、`sectionTimesContainer` 也表达不了「根数组」；另外 `timeSlots` 发的是空请求体，而页面请求带 `xqm` + `xqh_id`。这种情况下作息时间读不到（应用退化成「选用已有作息表」）。要修得动族适配器，并且得先确认 `xqh_id` 从哪里取。
- **页面环境会直接改变结果**：若页面把 `Array.prototype.filter` 改成永远返回空（`every` 永远返回真），现象是「这个学期没有课表数据」，跟真实原因毫无关系。运行流程因此不在关键路径上用这类方法，并在 `runImport` 开头自检运行环境。

## 未实测的部分（重要）

本适配器只依据该族**公开的接口形状**编写，没有在真实教务系统上跑过。以下几项是推断，第一次实测时
重点核对：

- 课表响应里行数组的键名（默认 `kbList`）与字段名；
- 节次时间接口的路径、容器与三个字段名（默认 `jc` / `qssj` / `jssj`）；
- 学期码 `xqm` 的两个取值（`3` / `12`）；
- `xnm` 是否被服务端采纳：页面自己的请求**不带** `xnm`，而适配器会发；若被忽略，切到别的学期仍会拿到当前学期的课表，而且**不报错**；
- 请求体里除 `xnm`/`xqm`/`kzlx` 之外的参数是否需要填别的值。

任何一项对不上，都优先改取值；改不动才写 `override.js`。
